#+TITLE: Guile 3.0.10 posix_spawn Segfault on FreeBSD 14 (Bug #79494)
#+AUTHOR: aygp-dr
#+PROPERTY: header-args :mkdirp t

Research log and submission-ready evidence for the Guile spawn crash that the
=(llm utils subprocess)= module works around. Claims below are annotated using
the property-drawer convention from https://wal.sh/research/annotation-systems/
(=:VERDICT:= / =:VERIFIED_AT:= / =:VERIFIED_BY:= / =:FINDING:= / =:STATUS:=).

* Summary
:PROPERTIES:
:CUSTOM_ID: summary
:VERDICT: correct
:VERIFIED_AT: 2026-06-22T04:40Z
:VERIFIED_BY: claude-code
:FINDING: Reproduced SIGSEGV from a clean system*/open-input-pipe call on FreeBSD 14.4-RELEASE-p6 with guile3-3.0.10; backtrace points at posix_spawn_file_actions_addclosefrom_np in libc.so.7.
:STATUS: closed
:END:

Guile's =system*=, =open-pipe*=, and =open-input-pipe= crash the process with
SIGSEGV on FreeBSD 14 because gnulib's bundled =posix_spawn= replacement is
incompatible with FreeBSD's native
=posix_spawn_file_actions_addclosefrom_np()=. The bug was first documented on
FreeBSD 14.3; this log confirms it persists after upgrading to 14.4-RELEASE-p6.

rebuilt by the package upgrade. The crash survived the rebuild.

:CUSTOM_ID: reproduction

Minimal, dependency-free reproduction:

#+begin_src bash :eval no
# system* path
guile3 -c '(system* "/bin/echo" "spawn-ok")'
# popen path
guile3 -c '(use-modules (ice-9 popen)(ice-9 rdelim)) \
  (let ((p (open-input-pipe "echo pipe-ok"))) (read-line p) (close-pipe p))'
#+end_src

Observed: =Segmentation fault (core dumped)=, shell =rc=139= for both.

* Root cause
:PROPERTIES:
:CUSTOM_ID: root-cause
:VERDICT: disputed
:VERIFIED_AT: 2026-06-22T04:40Z
:VERIFIED_BY: claude-code
:FINDING: The faulting symbol (posix_spawn_file_actions_addclosefrom_np) and the upstream bug text agree on the gnulib-vs-FreeBSD posix_spawn mismatch. We have NOT independently read libguile/posix.c do_spawn on this build, so the exact call path remains attributed-not-proven here.
:STATUS: open
:END:

Per upstream (Bug #79494): Guile links gnulib's replacement =posix_spawn=, which
is incompatible with FreeBSD's native
=posix_spawn_file_actions_addclosefrom_np()=. The observed frame #0 is
consistent with that explanation. Treat the precise =do_spawn= call path as
upstream's claim until verified against this exact 3.0.10 build's source.
